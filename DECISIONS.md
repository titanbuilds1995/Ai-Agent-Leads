# DECISIONS

Choices made autonomously where the operator inputs were blank or the spec was ambiguous. Change any of them in `config.yaml`; none are hardcoded.

| # | Decision | Reasoning |
|---|----------|-----------|
| 1 | **Price range $150k–$750k**, counties Miami-Dade / Broward / Palm Beach, types SFR / townhouse / 2–4 unit / land, condos and mobile homes excluded | Blank in the operator inputs. $150k–$750k covers the South Florida wholesale sweet spot; condos carry HOA/approval friction and were not in the listed types. |
| 2 | **MAO = ARV × 0.70 − repairs − $15,000**, EMD $5,000, 14-day close | Formula and numbers taken from the example in the prep document. |
| 3 | **HOT/WARM "within X% of MAO" is measured relative to MAO** (`(list − MAO) / MAO`), not relative to list | "List price within 20% of MAO" reads most naturally as a band around MAO. Both numbers are in `config.ranking`; swap the formula in `ranking.rate()` if you meant the other. |
| 4 | **Model `claude-sonnet-5-5`, effort `low`, structured JSON output** | Prompt said "claude-sonnet-4-5 or newer"; 5.5 is the current Sonnet. Low effort is enough for remark classification and keeps the 500–1,500 listings/day inside the $5–15/day budget. Pricing table for the cost counter is in `config.llm_pricing_per_mtok`. |
| 5 | **Rules fallback for every LLM call** (`TITAN_LLM=rules`, or automatically when the key is missing, the API errors, or the model refuses) | Tests must be deterministic and the pipeline must never stall on an API outage. Every score records `method` (claude or rules) so you can see which ran. A Claude score ≥ 40 with no cited phrase is rejected and re-scored by rules. |
| 6 | **Reply responses are template-based, not LLM-written** | Section 8 says "never invent facts, never commit beyond config terms". Templates filled only from `config.outreach.terms`, MAO and the counter number are the only way to guarantee that. Claude is used for *classifying* ambiguous replies (rules handle the confident ones first). Questions outside the config facts (assignment, appraisal, lease-back…) are escalated as NEEDS_CALL instead of answered. |
| 7 | **First-touch emails: Claude drafts in your voice, then a validator checks** no HTML, no links, has the street, mentions cash, asks a question, 35–220 words, no dollar figure. Failing drafts fall back to one of 4 templates (plus a multi-listing template). | Keeps voice quality when the API is on and guarantees the hard rules either way. |
| 8 | **SMS templates only** (4 variants, all < 160 chars, rotated per agent/day) | A 160-character text has no room for voice and every word must be exact (company name, phone). |
| 9 | **Reply mode mapping**: `DRAFT_FOR_APPROVAL` → first touches and replies are drafts; `AUTO_SEND_FIRST_TOUCH` → first touches and the 7a written offer are sent, conversational replies are drafts; `FULL_AUTO` → everything sent | Matches the one-week autopilot path in the prep doc. The 7a text-to-email handoff is "automatic, no human step", so it sends in both AUTO modes; in DRAFT mode it lands in `Titan/Review` and the "just sent the written offer" text is **not** sent (it would be a lie). |
| 10 | **SMS counters do not bridge**; a positive text (INTERESTED / ASK_FOR_OFFER / COUNTER) always triggers the 7a handoff and HOT_LEAD | Section 7a explicitly says the handoff applies to all three classes. Bridging logic (halfway number once, then escalate) applies to email counters only. |
| 11 | **Twilio has no drafts**, so in DRAFT mode texts are stored as `status=draft` rows and written to `reports/drafts/YYYY-MM-DD/` for review; they are never sent | Only way to honor "DRAFT_FOR_APPROVAL" for a channel without a drafts folder. |
| 12 | **Outside the 9–6 ET weekday window, texts are `queued`**, and `check-replies` (every 15 min) flushes them once the window opens | The 5:30am run is outside the window by design; queueing avoids a second scheduler. A 9:05am weekday cron line also runs an outreach-only pass. |
| 13 | **Agents are stored only for listings that pass the filters** | PII hygiene: no reason to hold contact data for a condo in Orlando. Office-line detection therefore counts shared numbers only among stored agents. |
| 14 | **Enrichment confidence gate**: emails are only used when confidence ≥ `outreach.email_min_confidence` (default medium). `pattern+smtp` = medium, `pattern+mx` (catch-all server) = low. | Bounce rate is the deliverability killer; low-confidence guesses are stored for Rodrigo but not emailed. |
| 15 | **Comps come from the Zillow actor's "recently sold" filter, pulled once per county per day and cached** (`comps_cache`), then filtered per subject (0.5 mi, ±25% sqft, same type, 6 months, min 3; widen to 1 mi; else Zestimate; else list price). `arv_method` and `comp_count` are stored so weak valuations are visible. | One actor run per county is far cheaper than one per property. |
| 16 | **Repair tier is keyword-driven** (gut > heavy > moderate > cosmetic, first match wins), default moderate, floor $10k | Remarks are the only condition signal available pre-walkthrough. |
| 17 | **Default actor ids** `epctex/realtor-scraper`, `maxcopell/zillow-scraper` with tolerant field mappers; raw actor output is saved to `raw/` | The exact output schema could not be verified without an Apify token (see BLOCKERS). The mappers accept the common field-name variants; if a field comes back empty on the first live run, the raw dump shows the real name to add. |
| 18 | **Zillow URLs filter "new in last 30 days"**; the "price reduced" view comes from the Realtor.com URL (`show-price-reduced`). Price cuts are also detected from price history on either source. | Zillow exposes price cuts only as a sort, not a filter. |
| 19 | **Dedupe key** = normalized street (directionals and suffixes abbreviated, unit kept) + city + state + 5-digit zip | Realtor "107 N.W. 11th Street" and Zillow "107 NW 11th St" must be one row. |
| 20 | **STOP handling**: STOP/unsubscribe on any channel adds agent id, phone and email to `do_not_contact`, cancels queued/draft outreach to that agent, and no reply is sent (Twilio sends the carrier-mandated confirmation itself). | CAN-SPAM / TCPA. |
| 21 | **Cron**: 5:30 run-daily, */15 check-replies, 7:00 report, 9:05 weekdays outreach pass, all in `America/New_York` via `CRON_TZ` | As specified; the extra 9:05 pass is decision #12. |
| 22 | `scoring.signals` weights live in config and are shared by the Claude prompt and the rules scorer | So the two methods stay comparable and you tune one place. |
| 23 | **"as-is" alone on an otherwise clean listing counts half** | "As-is" is boilerplate on many renovated listings; it only means motivation next to "needs work", "cash", damage, estate or distress signals. |
| 24 | **Voice is a file, not a prompt string.** `docs/style/RODRIGO_WRITING_STYLE_GUIDE.md` is read at draft time and inserted into the Claude system prompt; `outreach.example_emails` holds five verbatim agent/office-facing emails from `docs/style/style_examples.md`. Templates, offer email and canned replies were rewritten to the guide (sign-off `Best regards,` / `Best,`, signature `Rodrigo Gayoso / Principal | Titan Realty / (561) 405-7379 / West Palm Beach, FL`, no website line so the no-links validator holds). | Rodrigo supplied the guide on 2026-10-23; one file to edit when the voice drifts, and the guide is cached per process so it costs one read. |
